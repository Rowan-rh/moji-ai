# 默记 (MoJi) — 产品需求与技术规格文档 (PRD & Tech Spec)

> **产品定位**：一款基于 AI 语义理解、彻底告别“正则表达式规则维护地狱”的开源安卓全自动静默记账软件。  
> **核心理念**：*“默默记好每一笔账，不打扰你的生活。”*

---

## 一、 背景与痛点分析

目前市面上的安卓自动记账方案（如传统开源自动记账插件 + 第三方账本）普遍存在三大核心痛点：
1. **正则规则维护地狱**：依赖针对每个 App 页面和通知编写固定的正则表达式或控件路径，一旦微信、支付宝、美团或银行 App 改版升级，规则立即失效。
2. **复杂资金流转场景账目混乱**：遇到微信零钱提现/充值、余额宝转入转出、储蓄卡还信用卡/花呗、淘宝退货退款、同事微信转账 AA 分摊餐费时，传统工具往往将其误记为普通“支出”或“收入”，导致月度收支虚高、资产余额对不上。
3. **中间件与账本割裂**：识别插件与记账软件分离，用户需要繁琐地配置资产映射、分类映射，且频繁弹窗打断支付流程。

---

## 二、 核心产品需求清单

### 1. 自动触发与无感交互（纯后台静默模式）
- **三模无感采集（免 Root）**：
  - **通知栏监听 (`NotificationListenerService`)**：实时捕获微信支付、支付宝、云闪付、银行 App 动账通知及 955xx 银行扣款短信。
  - **微信/支付宝及拼多多/抖音/京东等电商无障碍兼容识别 (`SelectToSpeakService` + `PaymentAccessibilityService`)**：通过 `com.google.android.accessibility.selecttospeak.SelectToSpeakService` 兼容入口与 `FLAG_REQUEST_ENHANCED_WEB_ACCESSIBILITY` 突破微信支付与账单详情容器节点限制；仅遍历匹配当前目标应用包名的活跃窗口（深度 50、节点上限 500），配合 `150/450/1000/1800ms` 四阶延迟探测与单笔详情锚点校验，全面支持 **微信支付、支付宝、云闪付、拼多多 (`com.xunmeng.pinduoduo`)、抖音/抖音极速版 (`com.ss.android.ugc.aweme` / `.lite`)、京东 (`com.jingdong.app.mall`)、淘宝 (`com.taobao.taobao`)、天猫 (`com.tmall.wireless`)、美团/美团外卖 (`com.sankuai.meituan`)、饿了么 (`me.ele`)、唯品会 (`com.achievo.vipshop`)、小红书 (`com.xingin.xhs`)** 的「支付成功 / 拼单成功 / 账单详情 / 订单详情」页面结构化提取，并自动过滤账单列表页、订单列表页、购物车结算页与微信支付服务号历史卡片流。
  - **iCost 模板「原价 · 优惠了多少 · 实扣多少」解析与全链路展示 (`AiAccountingEngine.extractPriceBreakdown`)**：自动缝合电商详情页跨节点拆分的整数与小数金额（如 `¥ | 29 | .90`），优先提取 `实付款 / 实付金额 / 实扣 / 应付总额` 作为入账实扣金额 (`amountCents`)，同时提取 `商品总价 / 原价` 与 `已优惠 / 共减 / 百亿补贴 / 店铺优惠 / 平台优惠 / 多多支付立减 / 抖音支付优惠 / 京豆 / 红包` 作为优惠金额 (`discountCents`)，按 **`原价¥X.XX · 优惠¥Y.YY · 实扣¥Z.ZZ | 商品名称 · 支付方式`** 模板格式生成备注，并在流体云胶囊、首页账单列表标签与账单详情页同步展示。
  - **Android 11+ 免 Root 截屏端侧 OCR 兜底与快捷设置磁贴 (`OcrTileService`)**：当目标支付/账单窗口节点缺失金额或用户下拉控制中心点击「默记识屏记账」磁贴时，调用 `AccessibilityService.takeScreenshot` 与内置离线中文 OCR（按 Y 轴行聚类与 X 轴排序还原左右分栏键值）完成识账。
- **核心四要素留存、双规则重复判定（默认不录入 + 弹窗点“录入”才入账）与一加流体云实况胶囊**：
  - **核心计费四要素持久化与无明确时间强制拦截 (`TransactionEntity` Room v5)**：留存 **订单唯一 Key (`orderKey`，优先取平台交易单号/订单号，其次取商户单号)**、**实际购物发生时间 (`timestamp`，从账单支付时间/创建时间解析，严格区别于截图时间 `capturedAtMillis`)**、**交易金额 (`amountCents`)** 与 **购物商品数量 (`itemQuantity` / `quantityDesc`)**；若采集页面缺失明确的支付/交易时间（如仅展示“支付成功 + 商户 + 金额 + 完成”的过渡页），一律拦截不予录入。
  - **同笔/重复判定、跨应用同单双向融合与默认不录入机制 (`CapturePipelineCoordinator`)**：
    1. **规则 1（单号交叉与内嵌匹配）**：如果订单的唯一 Key（订单号 / 交易单号 / 商户单号）交叉一致，或一方备注/原文内嵌了另一方的订单编号（如微信账单 `京东-订单编号3673486013948720` 与京东订单 `3673486013948720`），100% 认定为同一笔账单；
    2. **规则 2（同支付时间或同登记时间 + 同金额匹配）**：无论双方是否有订单号或跨渠道单号不同，只要 **「（实际交易发生时间 OR 采集登记时间）+ 金额」一致**，100% 认定为同一笔账单；
    3. **规则 3（电商订单详情 ↔ 支付通道账单详情跨应用同单融合）**：当一侧为拼多多/京东/淘宝/天猫/抖音等电商订单详情，另一侧为支付宝/微信/银行的通道账单（如 `拼多多平台商户`、`江苏京东信息技术有限公司`），且金额一致、同属一个平台且下单与支付时间紧邻（或同日日期前缀兜底）时，自动认定为同一笔交易，保留电商侧的具体店铺名、商品标题、原价与优惠明细及电商订单号，同时融合支付侧的真实扣款银行卡/花呗账户、支付交易单号与商户单号。
    - **点开详情补充细节 vs. 重复拦截的智能分流**：
      - 当命中上述同笔规则且新采集的详情页包含原记录缺失的字段（如 `订单号`、`支付单号`、`商户单号`、`扣款账户`、`具体店铺名`、`商品说明备注`、`商品数量`、`立减优惠金额`）时，自动将新细节增量合并至原账单（并同步校准扣款账户余额），顶部流体云弹出 **「已补全账单详情」**；
      - 当原账单各项细节早已齐全、无任何新字段可补充时，判定为纯粹的重复扫描：**默认绝不写入数据库**，在顶部流体云胶囊与通知中心提示 **「检测到疑似重复 · 未录入」**，仅当用户主动点击 **「录入」** 按钮时才强制入账。
  - **识账截图本地保存与生命周期联动 (`BillScreenshotStorage`)**：无障碍详情页与端侧 OCR 识别到的账单截图自动以 WebP 格式保存在应用沙盒 `files/bill_screenshots/`，账单详情页通过后台线程 (`Dispatchers.IO`) 异步解码展示原图，撤销或删除账单时自动清理无引用的本地截图文件。
  - **支付账号智能匹配 (`matchWalletForPayment`)**：银行卡（储蓄卡/信用卡）优先根据后 4 位数字尾号（如 `3354`、`8848`）及卡种匹配；花呗、白条、零钱、账户余额/余额宝等根据汉字名称与别名匹配，自动扣减对应账户余额或增加信用账户待还欠款。
  - **一加流体云 (Fluid Cloud) 120Hz 挖孔延伸与缩回胶囊 (`RecognitionBanner` + `SilentBookkeepingNotifier`)**：通过 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS` 直接从前置摄像头挖孔 (`centerX, 19.5dp`) 向下拉出流体水滴连接带并撑开为曜石黑胶囊，配备抗锯齿 Canvas 自绘发光状态环、凝缩金额排印、正常入账一键「撤销」与疑似重复一键「录入」大热区按钮；当用户离开账单页、点击操作、上滑或超时后自动回吸缩进前置摄像头孔内，配合看门狗清理机制彻底杜绝悬浮窗卡死残留。
  - **面向未来云同步的 Room v5 底层数据结构**：在 `wallets`、`transactions`、`recurring_rules` 与 `capture_evidences` 表中内置 `syncUuid`（全局 UUIDv4）、`updatedAtMillis`、`deletedAtMillis`（软删除墓碑）、`syncRevision` 与 `syncDirty` 增量同步标记。
- **纯后台静默入账 + 系统通知栏三键快捷操作**：
  - 付款后无需人工点击确认弹窗，后台直接完成解析与入账，并推送一条系统通知提醒。
  - 通知栏自带 **「撤销入账」「切换分类（同步写入商户记忆库）」「标为待报销」** 三个快捷按钮，无需打开 App 即可在通知栏一键完成回滚、改分类或打报销标记。
- **国产 ROM 后台保活与 Android 13+ 受限设置一键诊断 (`RomKeepAliveGuideHelper`)**：
  - 自动检测机型厂商（ColorOS / HyperOS / OriginOS / HarmonyOS），提供 `NotificationListenerService.requestRebind` 一键重连、Android 13+「应用详情 ➔ 允许受限设置」一键跳转与后台电池白名单诊断。

### 2. AI 智能识别引擎（多模型兼容 + 商户记忆自学习 + 本地加权兜底）
- **通用大模型接入**：
  - **OpenAI 兼容接口**：支持自定义 `Base URL`、`API Key` 与 `Model Name`（无缝对接 DeepSeek、通义千问、硅基流动、OpenAI 或局域网 Ollama）。
  - **Google Gemini 官方接口**：原生支持 Gemini Flash 等高速低成本模型。
- **动态上下文注入 (Context-Aware Prompting) 与商户记忆自学习 (`MerchantMemoryManager`)**：
  - 用户每次新增或编辑修正账单分类时，自动将该商户与目标分类、偏好账户写入本地商户记忆库；每次 AI 请求动态注入 **用户历史商户分类记忆**、**钱包列表（含银行卡尾号、别名、币种）** 与 **最近 15 笔可冲抵的消费账单**。
- **带排除词一票否决权重的离线语义引擎 (`WeightedCategoryClassifier`)**：
  - 在未配置 API Key 或手机断网时，自动启用内置本地高智商语义解析器：优先匹配商户记忆规则，再通过 `强信号词(+10) + 品牌词(+8) + 品类词(+6) + 排除词(-999 一票否决)` 评分模型精准分类（例如“美团外卖”自动排除购物/旅游归入“餐饮-三餐”）。
- **免分类「待梳理」状态与 Agent 账单/截图分类梳理引擎 (`AgentBillTriageEngine` & `AgentTriageBottomSheet`)**：
  - **免分类极速记账（`PENDING_TRIAGE_CATEGORY = "待梳理"`）**：在 `CategoryCatalog` 中预留系统过渡状态「待梳理」（映射 `setting_auto.webp` 图标，不污染自定义分类管理列表，且不触发 `MerchantMemoryManager` 误学）；记账计算器面板顶部提供「待梳理（交由 Agent）」快捷胶囊（或再次点击当前选中主分类取消选择切入「待梳理」），用户可只输金额直接入账；`AiAccountingEngine` 在未命中商户记忆且离线分类无关键词命中时亦自动落入「待梳理」。
  - **账单 + 截图联合梳理与一二级分类/规则自动提炼**：在「账本首页（存在待梳理账单时顶部提示胶囊 + 更多菜单）」「记账计算器」「分类管理顶栏」「智能记账 › 分类规则」提供 **「✨ Agent 梳理」** 主入口（手动新增分类/规则收纳于二级入口兜底）；`AgentBillTriageEngine` 综合账单截图 (`screenshotPath`)、抓取原文 (`rawCapturedText`)、商户、备注、时段（如深夜 `22:00–04:00`）与金额，输出「待梳理账单重分类归档」「建议新增一二级分类（自动匹配 81 枚 `.webp` 图标，如 `餐饮-夜宵`、`运动-球类`、`宠物-口粮`、`应用软件-云与AI`）」与「建议新增 `SmartConditionRule` / `MerchantMemoryEntry`」，支持逐项勾选与「一键采纳生效」原子化落库。

### 3. 全能钱包与资产负债管理
- **4 大账户类型**：
  1. **银行储蓄卡 (`DEBIT_BANK`)**：支持配置银行卡后四位（如 `8848`）及别名，供 AI 从银行扣款通知中精准定位。
  2. **数字钱包 (`DIGITAL_WALLET`)**：微信零钱、零钱通、支付宝余额、余额宝等。
  3. **信用/透支账户 (`CREDIT`)**：信用卡、蚂蚁花呗、京东白条、美团月付等。支持管理 **授信总额度**、**当前待还欠款**、**可用额度**、**账单日** 与 **还款日**。
  4. **现金/预付卡/其他 (`CASH_OTHER`)**：现金、饭卡、公交卡、海淘外币卡等。
- **净资产实时核算与真实余额锚点平账 (`reconcileWalletBalance`)**：
  - 自动汇总：`净资产 = 计入净资产的储蓄/数字钱包总额 - 信用账户待还总负债`。
  - 支持在账户详情页输入微信/银行卡当前真实余额或信用卡真实待还欠款，自动计算与账面余额的差额并生成一笔可随时撤销的 `BALANCE_ANCHOR` 平账补差流水。
- **全量快照备份恢复与多源 CSV 账单导入导出 (`BackupAndCsvTransferEngine`)**：
  - 支持导出与恢复带 `BackupSchemaGuard` 默认值保护的 `.mojibackup` 全量 JSON 快照（含钱包、账单、周期规则、商户记忆库、条件规则、快捷模板、存钱计划、信用卡分期计划、自定义分类/标签/汇率、定时提醒、外观显示、多账本与预算）。
  - 支持自动识别并预览导入 **微信支付官方账单 CSV、支付宝官方账单 CSV、钱迹 / iCost CSV**（内置重复流水指纹跳过），并支持导出标准 UTF-8 CSV 报表。

### 4. 七大真实交易形态与报销/优惠/手续费核算（解决“乱七八糟”的账务场景）
| 交易类型 | 枚举值 | 真实场景举例 | 钱包余额与报表联动规则 |
| :--- | :--- | :--- | :--- |
| **日常支出** | `EXPENSE` | 微信扫码买咖啡、美团外卖、打车 | 扣减储蓄/零钱余额（含 `feeCents` 手续费），或增加信用账户待还欠款；计入当月支出，同步统计 `discountCents` 优惠金额 |
| **日常收入** | `INCOME` | 发工资、奖金、理财收益、长辈红包 | 增加收款钱包余额；计入当月收入 |
| **内部转账** | `TRANSFER` | 招行卡充值到微信零钱、零钱提现到银行卡 | 转出钱包扣减，转入钱包增加；**不计入收支报表**，净资产不变 |
| **信用还款** | `REPAYMENT` | 招行储蓄卡还招行信用卡、余额宝还花呗 | 储蓄钱包扣减余额，信用账户恢复可用额度（减少待还欠款）；**不计入重复支出** |
| **退款/AA冲销** | `REFUND_OFFSET` | 淘宝退货退款、同事微信转账分摊 AA 午餐费 | 收款钱包恢复余额，同时自动关联原消费账单并扣减其净支出 `refundedAmountCents`（防止当月餐饮/购物支出虚高） |
| **借入款项** | `LOAN_IN` | 向朋友临时周转借入资金 | 收款钱包增加余额，联动资产页「总借入」统计 |
| **借出款项** | `LOAN_OUT` | 借钱给朋友或垫付资金 | 付款钱包扣减余额，联动资产页「总借出」统计 |

- **报销闭环与批量核销 (`reimbursable -> reimbursed` & `batchSettleReimbursements`)**：支持将消费账单标记为「待报销」，并在「批量报销核销中心」多选待报销账单后一键批量结算入账、恢复指定收款账户余额。
- **单笔分拆账单 (`splitExpenseTransaction`)**：支持在账单详情页将单笔消费（如超市综合采购）拆分为多个独立分类与金额的子账单，同时保持原付款账户总扣款金额严格不变。
- **可视化条件规则引擎 (`SmartRuleEngine`, `When -> Then`)**：支持按关键词、金额上下限、24 小时时间窗组合条件，自动改写分类/账本/附加标签、自动标为待报销或静默拦截非账单通知。
- **WebDAV 自托管云同步 (`WebDavSyncClient`)**：支持连接坚果云、Nextcloud、群晖 Synology 等标准 WebDAV 服务，一键上传或下载恢复 `.mojibackup` 全量快照。
- **GitHub 私有仓库 / 公开仓库 OTA 自动更新 (`AppUpdateManager`)**：支持通过单仓库只读 Fine-grained PAT（编译期 `local.properties` 注入或设置页动态配置）查询 GitHub Releases、通过 Release Asset API（`Accept: application/octet-stream`）流式下载私有仓库 APK、校验 `PK` 签名头并通过 `FileProvider` 调起系统安装器一键覆盖升级。

## 三、 技术栈与工程结构

- **开发语言与 UI 框架**：100% 原生 Kotlin + Jetpack Compose (Material 3)
- **本地持久化**：Room (SQLite)，全事务 (`withTransaction`) 保证账单与多钱包余额强一致
- **网络与序列化**：OkHttp 4 + Kotlinx Serialization JSON
- **核心代码目录**：
  - `app/src/main/java/com/moji/ai/data/`：枚举模型、Room 实体、DAO、数据库初始化及原子化账本仓库 `LedgerRepository`
  - `app/src/main/java/com/moji/ai/service/`：通知栏监听服务、无障碍页面抓取服务、滑动窗口防抖合并协调器 `CapturePipelineCoordinator`
